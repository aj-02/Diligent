## Introduced by the remediation, not inherited

38 objects exist in both `sources/` and `corrections/`, so each correction can be compared
against its own original. Net change:

| Rule | Added by the fix | Resolved by the fix |
|---|---:|---:|
| `SELECT_ENDSEL` | 13 | 5 |
| `FAE_NO_GUARD` | 2 | 0 |
| `DAD_NO_SORT` | 0 | 4 |
| `ORDER_PRIMARY` | 0 | 3 |
| `CLAUSE_ORDER` | 0 | 2 |
| `SELECT_IN_LOOP` | 0 | 2 |
| `HARDCODED` | 0 | 1 |

The remediation is net positive everywhere except one pattern. Closing a NOORDER finding
by rewriting `SELECT SINGLE` as

```abap
SELECT f1 FROM t INTO x UP TO 1 ROWS WHERE ... ORDER BY PRIMARY KEY .
ENDSELECT.
```

trades one ATC finding for two problems: it creates a `SELECT ... ENDSELECT` loop (itself
an ATC finding), and where the field list is not `*` the `ORDER BY PRIMARY KEY` is invalid.
`ZPME_SFORM_REPORT.abap:213` is the clearest example, inside `BEGIN/END OF CHANGE BY
SAP_ABAP 08.08.2026 FOR ATC` markers. `SELECT SINGLE ... ORDER BY PRIMARY KEY` — no
`ENDSELECT`, no rewrite — closes NOORDER without either side effect.

The two added `FAE_NO_GUARD` are in `ZFI_JV_TB.abap:595` and `ZFI_TAX_CREDIT_REPORT.abap`.
An unguarded `FOR ALL ENTRIES` on an empty driver table reads the whole target table.

## Repo hygiene

`ovl/atc/corrections/` holds 153 files that are only **51 distinct objects** — every object
is stored three times: a loose `.abap`, `ONGC_abapgit/src/`, and
`ONGC_abapgit/by_package/<PKG>/src/`. Three copies means three things to keep in step and
no single answer to "which one do I paste". Worth collapsing to one, but that is a
deliberate decision, not something I should do unasked.

## What this audit does not cover

- It reads source text. It does not compile. Every finding is a candidate for review.
- Native SQL (`EXEC SQL … ENDEXEC`) is skipped entirely — different dialect, different rules.
- `FAE_NO_GUARD` looks back 25 statements within the same unit. A guard set in a caller,
  or further back than that, will read as missing.
- `DAD_NO_SORT` looks for the `SORT` in the same `FORM`/`METHOD`. A sort done in a caller
  will read as missing.
- Dynamic SQL, `SELECT` built into a string, and ADBC calls are not analysed.
- `SELECT_IN_LOOP` counts what it sees; whether a join or `FOR ALL ENTRIES` is actually
  possible is a judgement call per site.
