## (atc-standing-preferences)


Standing preferences for ATC remediation work (see [[atc-project]]):

- **Never add a pseudo-comment (`#EC ...`) on a P1 finding without explicit approval.** P2/P3 pseudo is fine. P1 = real fix or wait.
- **Prefer a real solution over suppression**; use the minimum pseudo-comments necessary.
- **Comment out old code, never delete; add the new code below.** Active executable lines stay byte-for-byte verbatim in the same order.
- **Don't comment out a DML/write unless there's a real solution or a decision** (else block with an error MESSAGE naming the SAP Note).
- New-work author tag = `SAP_ABAP`; keep the original author when only consolidating change markers.
- Be concise.
- **No pseudo-code (`#EC`) unless there is genuinely NO real solution — at ANY priority.** Before resorting to a pseudo-comment, RESEARCH ONLINE for a real fix (SAP note / successor API / CDS). Pseudo is the last resort only. (Strengthens "real fix over suppression".)
- **Match the existing in-file change-marker format.** The ATC_FINDING_1 programs already contain prior ABAP7 corrections written as inline comments: `"Code remediation changes S4 2025 Conversion Begin of change ABAP7` … `"Code remediation changes S4 2025 Conversion End of change ABAP7`. Use that exact style for new changes in these files (not a different 5-star format), for consistency.
- **Line-number drift:** the ATC worklist `LINE` does NOT map 1:1 to the downloaded `.txt` line. Always verify by CONTENT (match the expected statement/keyword at/near the line; search ±a few lines) before editing — blind line-number edits land on the wrong line (e.g. an `#EC` on a `SORT`).
- **NEVER trust the bash mount for file completeness in the qatc folders — use Read.** Burned 2026-07-19: bash `wc -l` / `tail` reported `#SCL#KNA1.txt` truncated at 1211, `#CCC#SAPFOTC_DELVBILL.txt` at 101 lines, `CL_MA_WH_DASHBOARD CM016` at 108 lines with no ENDMETHOD, and 35 files across ATC_FINDING_1/2 as "incomplete". The Read tool showed ALL of them complete (KNA1 continues past 1274, SAPFOTC ends ENDFORM at 113, CM016 ends ENDMETHOD at 166). The bash mount serves stale/partial content for these paths. I reported two bogus HIGH "re-extract the source" warnings to Vaibhav before catching it. **Structural checks (IF/ENDIF, FORM/ENDFORM, tail inspection) must be run on Read output, not bash.** Related to the older note that file tools and the bash mount can show different states.
- **BDC rule CHANGED 2026-07-19 (supersedes the old rule in [[atc-cipla-reference-doc]]).** The earlier rule was "if the CALL TRANSACTION is a BDC (`USING bdcdata`) → do NOT change". Vaibhav now says: **convert BDC to a function module / API where a real solution exists**; leave it only where none is found. Old rule is dead — do not apply it.
- **Cross-check every candidate against the findings worklist BEFORE rewriting.** Proven on the ATC_FINDING_1 BDC sweep (2026-07-19): of 11 BDC calls in the folder only 3 were actually ATC-flagged. The source-list (ME01) and CK74 BDCs had **0 findings**, and the SM37 / MBC1 programs' findings were against unrelated tables/data elements. Matching a code pattern is NOT evidence the code is flagged — grep the worklist by object name first, or you rewrite working code for nothing.
- **Custom-namespace append fields block master-data API conversion.** cipla's vendor BDCs (`FORM update_custom_fields`, XK02) push ONLY `/CCC/*` and `/SCL/*` append fields on LFA1/LFB1 — no standard fields. `VMD_EI_API` / `CMD_EI_API` won't carry those unless the appends are registered with the CVI extension (BAdI/DDIC work), so a swap silently drops them. Check for `'<TABLE>-/NS/FIELD'` patterns before promising a BDC→API conversion.
- **Default scope = ALL objects, including HR / EHS / HSE.** Do NOT exclude them and do NOT mark them as "false positive" by default — they are to-be-done like any other object. The HR/EHS/HSE = false-positive/out-of-scope treatment was **specific to the ONGC / OVL project only** and must not carry over. Only exclude a category when explicitly told for that project.

**Why:** This is a regulated S/4 conversion where mechanical suppressions hide real gaps and a wrong edit to active code can change runtime behavior.

**How to apply:** Before touching a P1 finding, read its SAP Note (note that "semantic" Usages findings, e.g. note 2227532, may not clear via a mechanical FM→BAPI swap). Distinguish real fixes from fit-gap (functional, no code fix). Full method map is in `learning/ATC_S4_REMEDIATION_PLAYBOOK.md` in the project folder.

## (atc-change-marker-rule)


When applying ATC remediation change markers (`" ...**BEGIN OF CHANGE BY ABAP7 <date> FOR ATC` / `**END OF CHANGE...`), do NOT stack two markers back-to-back or nest a new marker block around code that is already inside an existing change block.

**Why:** Vaibhav (2026-07-04): "do not put 2 remarks one after the other; if there is a remark already (begin of change) don't put another and repeat the same code." Many cipla programs were already partially remediated (e.g. the ZFI/ZMM/ZPM batch carries `**...BY ABAP7 25.06.2026` markers + inline `#EC` pragmas). Re-wrapping those in my own BEGIN/END and re-commenting the old (already-commented) lines produces duplicate markers and repeated dead code.

**How to apply:**
- Before wrapping a statement, check if it (or the line above) already has a `**BEGIN OF CHANGE` marker or an inline `#EC` pragma. If so, edit *in place*: add just the needed pragma to the existing line, or change the code inside the existing block — do NOT open a new BEGIN/END block, and do NOT duplicate/re-comment the original line that's already commented.
- Only add a fresh BEGIN/END block around statements that have NO existing marker.
- For a pure pragma add on an already-changed line, append the pragma inline (e.g. a second `#EC ...`) rather than a whole new marker block. A single line may legitimately carry two `#EC` pragmas (e.g. `[2877717] [3404390]`), but must not get two BEGIN/END comment blocks.

**A `#EC` pseudo-comment MUST start with a leading `"` — it is a comment.** Vaibhav (2026-07-04): "when u put pseudo u need to put `"` before start of pseudo." Appending a bare `#EC CI_...` to a line with no existing comment (e.g. `CALL FUNCTION 'BAPI_X' #EC CI_USAGE_OK[..]`, or `... . #EC CI_FLDEXT_OK[..]`) is a SYNTAX ERROR. Correct: `"#EC CI_...`. When appending to a line that ALREADY has a `"` comment, put the extra `#EC` INSIDE that comment (no new `"`). **BUT Vaibhav does NOT want two `#EC` pseudos stacked on one line ("again double pseudo code has been used", 2026-07-04) — even one-quote-two-tokens is unwanted.** If a line already carries a pseudo and a new finding needs closing, prefer the REAL fix instead of a second pseudo: for `TYPE <table>-<f>` refs → **decouple to the data element** (`TYPE kondn-knumh`→`TYPE knumh`), which removes the object reference so the new note no longer applies (no pseudo needed at all). For a table READ that can't be decoupled (e.g. `SELECT … FROM kondn`, no successor), use a SINGLE correct-note pseudo — if the line already had a mismatched leftover pseudo (e.g. `[2226131]`/`[2689873]` on a `FROM kondn` read, where those notes don't apply to a condition-table read), replace it with the correct `[2220005]` rather than stacking. Net rule: **one pseudo per line max; if a second finding appears, real-fix it or replace the wrong one.** Bug caught 2026-07-04: my `prag()` helper appended `'#EC ...'` without the `"` on 23 ZPM lines — always build the pragma string as `'"#EC ...'` when the target line has no existing comment.

**BAPI field-length findings (notes 2438131 material / 2669857 object-no / 2628704 amount) — use `CONV #( )` on the value passed, per [[atc-mapping-references]] line "Field-length BAPI findings". BUT only if a narrower value is actually moved into the BAPI structure.** If the BAPI parameters are declared with the BAPI's OWN structure types (e.g. `ud_data TYPE bapi2045ud`, `lt_header TYPE bapi_alm_order_headers_i`), the extended fields auto-adopt and nothing is narrowed → there is NO CONV target → the `"#EC` marker alone is the correct close (do not invent a CONV). Check the fill code (`-material =`/`-matnr =`/`-menge =`) before deciding.

See [[atc-syntax-pitfalls]] and [[atc-standing-preferences]].

## (atc-approach-decision)


The ATC assets form **layers**, not alternatives. For any finding, decide which layer applies (see [[atc-project]], [[atc-correction-program]], [[atc-mapping-references]], [[atc-standing-preferences]]).

**1. Automation layer — `ZATC_RESULT_CORRECTION`** ([[atc-correction-program]]): the first pass for *standard, pattern-based* findings it already handles — field-length pragmas/CONV, SELECT→CDS rewrite (via ARS+DDLS), NOORDER SORT/ORDER BY, simplified-object AFLE/MFLE/DRC + `#EC CI_USAGE_OK`, DTEL/DOMA element swaps (from ZATC config), TRAN→BP/MIGO. Run it, then verify output. It deliberately *skips* things it can't do safely (SELECT *, non-SELECT DML, cursors) — those fall to the manual layer.

**2. Manual layer — playbook + reference** (`learning/ATC_S4_REMEDIATION_PLAYBOOK.md`, `learning/S4_ATC_Remediation_Reference.md`): for findings the program leaves alone or that need judgment — real FM→FM swaps (e.g. `BAPI_PO_GETDETAIL`→`BAPI_PO_GETDETAIL1`), structure field moves (BAPIEKET→BAPIMEPOSCHEDULE), VBTYP `CA`→`CL_SD_DOC_CATEGORY_UTIL` ranges, FSCM credit, master-data CMD/VMD, Settlement-Mgmt/LIS fit-gap, semantic notes (e.g. 2227532 where a BAPI swap won't clear it), and every P1 decision. Golden rule still governs: **no P1 pseudo without approval; real fix over suppression; comment don't delete.**

**3. Lookup/data layer** ([[atc-mapping-references]]): the shared knowledge both layers consult — `ARS_API_SUCCESSOR.xlsx` (is there a released successor + cloud/key-user ready?), `DDLS_BASE_FIELDS.txt` (which CDS view/element carries a table/field), `RVVBTYP_S4HANA_Mapping` (SD doc category), `Replacement_Objects_COKE` (FM→S4 FM), cookbooks (VBUK/VBUP, VBFA, index-table, pricing, BP — deep per-area guidance), DDIC changes, obsolete tcodes, BAPI PDFs. **ZATC config tables** (`zatc_process_*`) hold DTEL/DOMA→new-element mappings + disposition — if a needed DTEL mapping isn't present, ASK Vaibhav for the table data.

**Decision flow per finding:**
1. Standard pattern the program covers? → use/trust the program's fix, verify syntax + that the change marker/pragma is right.
2. Program skipped it (SELECT *, DML, cursor) or it needs a functional/real fix or is a semantic note? → manual layer, using playbook + reference + the right cookbook.
3. Need a table→CDS or DTEL/DOMA mapping? → ARS/DDLS first; if DTEL not found, ask for ZATC table data.
4. P1 → real fix or wait (approval for any pseudo). Fit-gap → no code change.

**When fixing the PROGRAM itself or writing a manual fix, match its conventions:** the program's defensive guards encode the playbook's gotchas — same change-marker format, same pragmas (`CI_FLDEXT_OK`/`CI_USAGE_OK`/`CI_NOORDER`/`CI_DB_OPERATION_OK`), guard-before-transform bug-fix style.

## (atc-syntax-pitfalls)


Bugs the customer found when **activating** my ATC code changes (cipla `ATC_syntax_document.docx`, 2026-06-30). Every automated SELECT/retype rewrite MUST guard against these. **Why:** activation failed (syntax errors) on these patterns — they passed my text checks but not the ABAP compiler. **How to apply:** bake each rule into the rewrite engines and the triple-verify.

1. **Non-strict `ORDER BY PRIMARY KEY UP TO 1 ROWS` is INVALID.** `UP TO n ROWS` must sit right after the field list, not after ORDER BY. Correct: `SELECT <fields> UP TO 1 ROWS INTO <tgt> FROM <src> [WHERE <c>] ORDER BY PRIMARY KEY.` + `ENDSELECT.` (Fixed across all 5 folders via fix_upto, 462 stmts — keep the rule.)

   **1b. CRITICAL (smart-form activation, 2026-06-30): putting `UP TO 1 ROWS` BEFORE `INTO` makes the statement STRICT → then EVERY host variable must be `@`-escaped, fields comma-separated, `ORDER BY` before `INTO`, `INTO @tgt UP TO 1 ROWS` last.** Error if not: *"Either L_XEKPO-MWSKZ has to be escaped using @ or qualified by a table name."* So **do NOT produce the half-strict `SELECT a b UP TO 1 ROWS INTO wa FROM t WHERE x = hv …`** (mixes strict UP-TO-order with un-@ host vars). USE THE PROVEN STRICT FORM (worked F2–F5 + smart forms): `SELECT f1, f2 FROM src [FOR ALL ENTRIES IN @itab] WHERE col = @hostvar AND … ORDER BY f1, f2 INTO @tgt UP TO 1 ROWS.` + `ENDSELECT.` @-escape ALL: WHERE RHS operands, `FOR ALL ENTRIES IN @`, `INTO @` (don't double-@ an already-`@data(...)`); comma-separate the field list AND the ORDER BY list; ORDER BY = the selected fields (or PRIMARY KEY only for `SELECT *`). Build the @-escaper carefully: strip inline comments (codeonly) BEFORE joining the old statement, keep spaces around operators, don't create `,,`.

2. **When converting `SELECT SINGLE` → loop form, the `SINGLE` keyword MUST be removed.** Bug: `SELECT SINGLE * UP TO 1 ROWS INTO wa … ORDER BY PRIMARY KEY. ENDSELECT.` → error *"ORDER is not allowed here. '.' is expected."* Correct: `SELECT * UP TO 1 ROWS INTO wa …`. (My fix_upto stripped only `SELECT` and left `SINGLE` inside the field list — strip `^SELECT\s+SINGLE\s+`, not `^SELECT\s+`.)

3. **`ORDER BY PRIMARY KEY` is only valid with `SELECT *` (or when the full key is in the field list, in key order).** On a **projection** (partial field list) where key fields aren't selected → errors *"The field <X> from the ORDER BY clause is missing in the SELECT list"* / *"Order by f1..fn"*. Fixes: (a) drop the ORDER BY (developer did this for the CDPOS/CHANGENR case), or (b) use **`ORDER BY <explicit key fields>`** e.g. `ORDER BY EBELN, EBELP` (not PRIMARY KEY). So the NOORDER engine must NOT append `ORDER BY PRIMARY KEY` to a non-`*` SELECT unless every primary-key field is in the SELECT list.

4. **VBTYP/VBTYP_N retype must change ONLY the data element after `TYPE`/`LIKE`, never the component/variable name.** Bug: `vbtyp_n TYPE vbtyp_n,` → `vbtypl TYPE vbtypl,` (renamed the field → breaks all `-vbtyp_n` references). Correct: `vbtyp_n TYPE vbtypl,` (keep name, change type only). Same for `VBTYP TYPE VBTYP` → `vbtyp TYPE vbtypl`. Regex must target only the post-`TYPE`/`LIKE` token, not every `vbtyp*` on the line.

5. **Strict Open SQL requires a COMMA-separated field list.** When a SELECT becomes strict (uses `@` host vars, `@DATA(...)`, `INTO TABLE @DATA`), a space-separated list → error *"SELECT LIST must be separated using commas."* Correct: `SELECT knumv, kposn, stunr, …`. Any rewrite that introduces `@`/`@DATA` (or targets a CDS) must also comma-separate the field list AND escape every WHERE host var with `@` (`WHERE knumv = @ta_vbrk_d-knumv AND kschl = @co_jtc1`).

6. **CDS-view swaps: drop `CLIENT SPECIFIED` and the `mandt = sy-mandt` filter.** When `FROM konv` → `FROM v_konv_cds` (or any CDS), remove `CLIENT SPECIFIED` and any explicit client/`mandt` condition (the CDS handles the client). Leaving them in breaks activation.

7. **Removing a `%_HINTS <db> '...'.` line strips the SELECT's terminating period** (the hint is usually the LAST clause and carries the `.`). Commenting it out leaves the SELECT with no period → activation error. Fix: when the removed hint line's codeonly ends with `.`, emit a lone `.` (same indent) in its place. (Caught in FINDING_2 ENHO run 2026-07-01, ZMM_CHANGE etc.) Only remove NON-HANA hints (`MSSQLNT`/ORACLE/DB6…); keep `%_HINTS HDB` (valid on S/4).

8. **Multi-line SELECT SINGLE with interspersed full-comment lines (`*`/`"`):** exclude comment lines from the parsed/joined statement (compiler ignores them) but keep them in the commented-old block; carry any pass-1 inline `#EC` pragmas from the old lines onto the rebuilt SELECT line (`… UP TO 1 ROWS. "#EC CI_FLDEXT_OK[..]`). Statement-end detection must SKIP comment lines (a mid-statement `* note.` ending in `.` must not be treated as the statement end). This recovered ~105 select-singles in FINDING_2 that were otherwise skipped.

9. **Compat CDS-VIEW reads (`V_VBUP_S4`, `V_VBUK_S4`, `V_VBUK_S4`, `V_KONV`, and any `V_*_S4`/CDS view) REQUIRE STRICT Open SQL — a plain FROM-swap is NOT enough.** Even though swapping `FROM vbup`→`FROM v_vbup_s4` looks trivial, the view forces strict syntax: **comma-separated field list**, **`@`-escape host variables (RHS operands ONLY — the column name on the LHS of a WHERE stays BARE)**, `INTO TABLE @itab`, `FOR ALL ENTRIES IN @itab`. Non-strict (space-sep fields, no `@`) → activation error. Correct (Vaibhav-confirmed 2026-07-03): `SELECT vbeln, posnr, gbsta INTO TABLE @ta_vbup FROM v_vbup_s4 FOR ALL ENTRIES IN @ta_vbap_tmp WHERE vbeln = @ta_vbap_tmp-vbeln AND posnr = @ta_vbap_tmp-posnr.` — note `WHERE vbeln = @...` NOT `WHERE @vbeln = @...` (never escape the LHS column). INTO may sit right after the field list (before FROM) — that position is valid strict.

10. **Statement-end detection MUST use `rstrip()` before `endswith('.')`.** Bug (2026-07-03, replace.txt): `while not code(body(e)).endswith('.')` (no rstrip) skipped a real terminating line that had trailing spaces, so the rewriter **swallowed the following `IF sy-subrc = 0.`** → "No open IF" / "ENDFORM has no open FORM" cascade at activation. Always `code(body(e)).rstrip().endswith('.')`. After any block-rewrite pass, VERIFY `IF==ENDIF`, `FORM==ENDFORM`, `LOOP==ENDLOOP`, `CASE==ENDCASE` counts vs the backup — an off-by-one means a control statement was eaten.

11. **Whole-table `MOVE-CORRESPONDING <any_table> TO <fixed_table>` DUMPS `OBJECTS_TABLES_NOT_COMPATIBLE` at RUNTIME when the source has a deep/nested component (cipla ZQM_QA33_REPORT, dump 2026-07-30, line 319).** Context: an FLE remediation (note 2522971, `#EC CI_FLDEXT_OK`) replaced `APPEND LINES OF <fs_data> TO ta_qa33` with `MOVE-CORRESPONDING <fs_data> TO ta_qa33`, where `<fs_data>` is an `ANY TABLE` captured from a SUBMIT ALV via `cl_salv_bs_runtime_info=>get_data_ref`. The captured source row carries a deep/nested component; the table-level MOVE-CORRESPONDING recurses into it (`ab_JmoveCompNonFlatlike` → `CX_SY_MOVE_CAST_ERROR`) and terminates. It ACTIVATES fine (syntax OK) but dumps at run time. **Correct fix (Vaibhav-applied, works): loop line-by-line into a CONCRETE work area typed `LIKE LINE OF` the target, then APPEND** — the structure-level MOVE-CORRESPONDING only copies components that exist in the flat target, so the source's deep component is skipped:
```
DATA l_qa33 LIKE LINE OF ta_qa33.
LOOP AT <fs_data> ASSIGNING FIELD-SYMBOL(<fs_data1>).
  CLEAR l_qa33.
  MOVE-CORRESPONDING <fs_data1> TO l_qa33.
  APPEND l_qa33 TO ta_qa33.
ENDLOOP.
```
Rule: never emit a whole-table `MOVE-CORRESPONDING` from a dynamic/`ANY TABLE` source into a fixed DDIC-based table — always the line-by-line loop into a concrete work area.

12. **`FOR ALL ENTRIES` on a driver built by COPY + DELETE (or select-then-drive) can go EMPTY at runtime → the kernel DROPS the WHERE and scans the WHOLE table (perf collapse / timeout).** This is the runtime-performance twin of the "IS NOT INITIAL before FAE" rule: an empty FAE driver doesn't error — it silently returns/joins against the entire target table. The dangerous drivers are NOT the freshly-`SELECT`ed ones (those are covered by a following `IF sy-subrc EQ 0`), but the ones derived in ABAP: `DATA(drv) = src.` then `DELETE drv WHERE …` (can delete every row), `DELETE drv WHERE key NOT IN r_range`, or a `VALUE #( FOR … IN src )` constructor — any of which can leave `drv` empty. **Rule: every `FOR ALL ENTRIES IN @drv` whose driver was produced by a copy+DELETE / NOT-IN-delete / VALUE-constructor MUST be wrapped in `IF drv IS NOT INITIAL. … ENDIF.`** Inline `@DATA(target)` inside the guard is fine (declaration is compile-time hoisted; target just stays empty when skipped). Applied cipla ZQM_PACKAGING_GOOSE 2026-07-31: 6 unguarded FAEs (ta_stb_hologram→MARA/MAKT, ta_stb_rbstp→MAST, ta_stpo_rb→MARA/ZMM_MARA, lt_matnr→ZPP_PBM), all copy+DELETE or VALUE-built. Verify after: `IF==ENDIF` count unchanged-balanced. Detection heuristic that works: flag active `FOR ALL ENTRIES IN @x` where no enclosing/preceding `x IS NOT INITIAL` AND no `sy-subrc` guard from x's own SELECT; then read each and keep only the copy/DELETE/VALUE-built ones. See [[atc-standing-preferences]] (IS NOT INITIAL before every FAE) — this is the same rule, motivated by a real full-scan not just correctness.

13. **Decouple a `TYPE tab-field` reference ONLY for the field that was actually removed — not every field of a "simplified" table.** Coke `/CCEJ/RDMMPURR_PAYLIST_CREATE` 2026-07-31: NACH lost only VAKEY (note 2220005). If the field still exists on the table, leave the ref as `tab-field`. A same-named data element is NOT guaranteed to exist just because the field does.** Fastest existence signal at activation: the checker reports the FIRST unknown type by line — a decouple on an earlier line that passed is confirmed-valid. See [[atc-cipla-reference-doc]] (VAKEY→VAKEY_LONG rule) and pitfall #12 above.

**CDS-for-performance judgment (cipla ZQM_PACKAGING_GOOSE 2026-07-31, Vaibhav pushed to "use CDS everywhere for perf"):** CDS only speeds a read via **pushdown** — when ABAP currently joins/aggregates/filters in loops, fires a chatty multi-step FAE cascade, or pulls more rows than needed. CDS does NOT accelerate an already key-indexed single-table read (same execution plan + view overhead), and swapping a narrow N-field read for a broad standard view (e.g. `I_Product`) is usually a REGRESSION (materializes unused joins). Custom Z-tables have no CDS. So do NOT blanket-wrap indexed single-table FAE reads in CDS. The legitimate pushdown target in a BOM program is the MAST→STKO→STPO→STAS cascade (collapse to a JOIN), but that touches validity-date/alternative semantics = careful redesign, not a mechanical swap. Same honest-assessment stance as VIAUFKS (keep a valid non-deprecated table + perf-tune rather than force CDS).

## (atc-correction-program)


`ZATC_RESULT_CORRECTION` is Vaibhav's **automated mass ATC remediation engine** (source in ATC project `tool/ZATC_RESULT_CORRECTION_AI_C.txt`; known-bug list in `tool/ZATC_RESULT_CORRECTION_AI_C_Issues.docx`). See [[atc-project]], [[atc-mapping-references]], [[atc-standing-preferences]]. Author tags in code: EJX9007359/EJX9007360.

**Flow:** selection screen takes ATC run series (`p_id`, F4 from `satc_ac_resulth`), object range `s_obj`, subobject `s_name` (oblig.), remark `p_rem`, transport `lv_req` (oblig., must be Workbench K* — validated against e070 trfunction, rejects T/G/R), change markers `p_begin`/`p_end`, and `p_sim` simulation checkbox (default 'X'). It pulls findings via `cl_satc_api_factory->create_result_access->get_findings`, builds `it_final` (priority E→1/W→2/N→3, check title/message with &1-&4 params substituted, Note number parsed from param1-4 containing 'Note'), loads config tables, loops distinct programs, fetches source (PROG/FUGR/FUGS/SFPF/SSFO via `SVRS_GET_VERSION_REPS_40`; CLAS via `SEO_CLASS_GET_METHOD_INCLUDES`+`SEO_METHOD_GET_SOURCE`/`SEO_SECTION_GET_SOURCE`), then a big CASE on check_title/check_message applies the fix line-by-line.

**Standard change marker wrapping:** every fix brackets the change with `" <p_rem> <p_begin> <uname> <date> for ATC` / `" <p_rem> <p_end> ...`, comments the old line with `*`, inserts new line(s) below — never deletes (matches [[atc-standing-preferences]]).

**Per-check fix logic:**
- **Database Operations (SELECT/JOIN):** hard guard never touches `OPEN CURSOR`/`FETCH`/`CLOSE CURSOR` or a SELECT that is a cursor body (scans back 40 lines). For real SELECT/JOIN: look up table in `ars_api_successor` (type TABL) → successor CDS (KONV→V_KONV_CDS hardcoded); `cl_dd_ddl_field_tracker->get_base_field_information` gives base table/field. If CDS fields exist → `change_table` FORM rewrites SELECT (maps fields to CDS element names with `AS <oldname>` aliases, moves INTO after WHERE, `@` host vars, handles FOR ALL ENTRIES + JOIN + IN-lists). If no fields → comment + `#EC CI_DB_OPERATION_OK[note]`. **`SELECT *` kept unchanged; non-SELECT DML (UPDATE/MODIFY/INSERT/DELETE/dynamic SET) never rewritten** (appended as-is).
- **Field Length Extensions:** most messages → comment old + re-add line with `#EC CI_FLDEXT_OK[note]`. IMPORT ISSUE → add `accepting padding`. MOVE TYPE/LENGTH CONFLICT → wrap RHS in `CONV #( )`. OFFSET/LENGTH & OLD MOVE LENGTH → check `fle_topic_switch-matnr_target_mode`, skip if on.
- **Usages of Simplified Objects:** AFLE notes 2628704/2628699/2628706 → `amount_conv` (CONV with rollname); MFLE 2438131/2438110 → `material_conv`; DRC 2480067 → `drc_report_note`; all then add `#EC CI_USAGE_OK[note]`. Else read **config tables** by `srch_tem=param2, ref_obj_type=param3`; if `solution='X'` and `fix_by<>'FIT GAP'` and param3 = **DTEL/DOMA → replace the data element with `correction_value`** (the new dtel). TRAN priority-1 → `prgn_corr2` lookup → `replace_bp` (BP nav via cl_bupa_navigation) or `replace_migo` (MIGO_DIALOG). NON-STRATEGIC P2/P3 → comment + CI_USAGE_OK.
- **Simplified Transactions in Literals (P3):** comment + `#EC CI_USAGE_OK` on the quoted literal only.
- **SELECT without ORDER BY (NOORDER):** DELETE ADJ DUPLICATES / READ BINARY SEARCH / AT NEW/END / ON CHANGE OF / LOOP-EXIT → insert `SORT` before the loop (FORMs process_read/endat/process_change_loop/loop_exit, with duplicate-SORT guard). READ/MODIFY INDEX & EMPTY SELECT → `#EC CI_NOORDER`. cluster/pool/UP TO SELECT → rewrite with `ORDER BY PRIMARY KEY` (FOR ALL ENTRIES → CI_NOORDER). SELECT SINGLE not unique → `change_single` rewrites to `SELECT … UP TO 1 ROWS … ORDER BY <pk from dd03l minus MANDT> … ENDSELECT`. ALV factory → SORT t_table.
- **ADBC interface** → `#EC CI_ADBC_US`.

**Write-back:** `p_sim='X'` → `INSERT REPORT ZTEST_CHECK<n>_<user>` (test only). Else real update + backup to ZTEST_CHECK: PROG/FUGR via `RPY_PROGRAM_UPDATE`; CLAS via INSERT REPORT include + `CTS_WBO_API_INSERT_OBJECTS`; enhancement via `cl_enh_tool_hook->modify_hook_impl`; SSFO via `smartform_procee` (patch CO nodes, SSF_WRITE_FORM, activate); SFPF via `adobe_form_procee` (patch generated includes). Then `RS_ABAP_SYNTAX_CHECK_E`; ALV shows program/subobj/new/backup/Success-or-Syntax-error.

**How Vaibhav fixes BUGS (recurring defensive pattern — apply this style):** every bug fix is a *guard added before the transform*, never a rewrite of working logic. Examples in the code: cursor guard; non-SELECT DML guard (else `UPDATE knvv` keyword gets dropped leaving orphan `SET (lv_setexp2)`); SELECT * guard; skip `*` comment lines in period/'.' detection so a commented `.` doesn't end a SELECT block early; truncate inline `"` comments before appending ORDER BY/`#EC` so tokens don't land inside a comment; `split_string` won't break before a `-` component selector and glues `@DATA(...)`; restore commas lost by tokenizer inside `IN ( … )`; add `@` only to RHS of a comparison (`l_after_op`) so LHS CDS field names aren't prefixed; save `FOR`/`FROM` index before READ TABLE overwrites `sy-tabix`; REFRESH it_query before change_single to avoid a doubled SELECT; exclude MANDT/QALS-MANDANT from ORDER BY.

**Sibling program — `ZATC_RESULT_CORR_GENERIC_CORR`** (GitHub repo `vaibhavdiligent/ONGC-CST-Purchase-Date-Sharing-`, branch main, `ZATC_RESULT_CORR_GENERIC_CORR.abap`; base variant `ZATC_RESULT_CORR_GENERIC.abap` also there): a **P2/P3-only pragma applier/corrector**, NOT a code transformer. Differences from the main engine: (1) `DELETE it_final WHERE priority='1'` + in-loop skip — never touches P1. (2) Only acts on check_title FIELD LENGTH EXTENSIONS or SIMPLIFIED OBJECTS (`check_target_title`) and a broad ~50-message whitelist of FLE/usage variants (`check_target_msg`: MOVE/COMPARE/CONCATENATE/TYPE/STRUCTURE-COMPONENT/IMPORT/EXPORT/ASSIGN/CALL FUNCTION|METHOD GENERIC/OFFSET-LENGTH/NON-STRATEGIC-FUNCTION, etc.). (3) It does **no** SELECT→CDS rewrite, no SORT, no CONV — it just **appends/repairs the exact `#EC` pragma that ATC itself recommends**, read from `finding_ext-description_lines` (the line containing `#EC` → `note_corr`). If a line already carries `"#EC CI_USAGE_OK[` / `"#EC CI_FLDEXT_OK[`, it extracts the old note, matches in it_final, and rewrites with the correct `note_corr`. Same write-back (RPY_PROGRAM_UPDATE / CLAS include / enhancement hook), same p_sim, plus richer ALV (run_status Not processed/Processed/No change + status). **Where it fits:** the safe bulk P2/P3 pragma pass that uses ATC's own suggested exemption token — run it for mass field-length/simplified-object suppressions; use the main `ZATC_RESULT_CORRECTION` for real transforms and P1-aware logic. The repo also holds `TSD_ZATC_RESULT_CORRECTION.md` (tech spec), `ZATC_PROG_DOWNLOAD/UPLOAD/VER_ROLLBACK.abap`, `ZCHECK_ABAP_SYNTAX.abap`, `ZBDC_FM_MAPPER.abap`.

**Exact SORT/ORDER BY placement logic (FORMs — replicate these precisely):**
- `PROCESS_READ` (READ BINARY SEARCH): build `SORT <itab> BY <k1 k2…>` where itab = token after `READ TABLE` and keys = the **LHS field names of each `field = value` in the WITH KEY clause** (strip `@`, `"`, values). Insert the SORT **before the ENCLOSING LOOP** — scan upward through output tracking ENDLOOP(+)/LOOP(−) depth; insert before the unmatched LOOP. Dedupe: skip if that exact SORT line already present.
- `LOOP_EXIT` (LOOP…EXIT/RETURN/LEAVE): `SORT <looptable>.` (no BY) before the enclosing LOOP.
- `ENDAT` (AT NEW / AT END OF): `SORT <looptable> BY <at-field>.` before the LOOP.
- `PROCESS_CHANGE_LOOP` (ON CHANGE OF): `SORT <looptable> BY <component after the '-'>.` before the LOOP.
- `CHANGE_SINGLE` (SELECT SINGLE not unique): rebuild as `SELECT … (drop SINGLE) … UP TO 1 ROWS … <INTO> … <WHERE> … ORDER BY <PK fields from DD03L where KEYFLAG='X', excluding MANDT and `.`-include fields; else ORDER BY PRIMARY KEY> . ENDSELECT.`
- cluster/pool SELECT (or "UP TO n ROWS without ORDER BY"): comment the whole SELECT block, re-emit it with `ORDER BY PRIMARY KEY.` appended before the terminating `.`; **EXCEPTION: if the SELECT contains `FOR ALL ENTRIES` → append `"#EC CI_NOORDER` instead of ORDER BY** (ORDER BY not allowed with FAE).
- READ TABLE … INDEX / Empty SELECT → `"#EC CI_NOORDER`.

**Field-length CASE:** big list of messages (CALL METHOD/FUNCTION GENERIC PARAMETER, WRITE/SET/EXPORT/GET ISSUE, OFFSET/LENGTH-ACCESS, OLD *) → comment old + re-add with `"#EC CI_FLDEXT_OK[note]`. `IMPORT ISSUE` → add ` ACCEPTING PADDING .`. `MOVE/MOVE-LENGTH/OLD-ARITHMETIC/OLD-MOVE TYPE CONFLICT` → split line at first `=`, wrap RHS: `lhs = CONV #( rhs ).`. OFFSET/LENGTH & OLD-MOVE-LENGTH skipped if `FLE_TOPIC_SWITCH-MATNR_TARGET_MODE='X'` and priority>1.

**KNOWN SYNTAX-ERROR PATTERNS this program produces — ALWAYS syntax-check after a run (user-confirmed it sometimes breaks code):**
1. **MOVE→CONV on a multi-line statement** — it only captures the RHS on the finding line, so a statement whose value continues on the next line becomes `lhs = CONV #( partial ).` dropping the rest → compile error. (Guard: only CONV-wrap single-line assignments; else leave/flag.)
2. **SORT BY captured values/comments** — multi-line `WITH KEY` or dynamic/`(field)`/`WITH TABLE KEY` → `SORT itab BY f = val "#EC …` garbage. (Guard: keys must be plain identifiers, no `=`,`"`,`-`.)
3. **Premature `.` detection** — statement-end found on a `.` inside a string literal, decimal, or path → block split wrong; ORDER BY/ENDSELECT placed mid-statement.
4. **ORDER BY appended inside an inline comment** — truncate at `"` before appending (the program does; verify).
5. **CHANGE_TABLE / CHANGE_SINGLE tokenizers** mis-handle subqueries, JOIN, parentheses, host vars, `INTO CORRESPONDING`, `APPENDING`, `PACKAGE SIZE` → malformed Open-SQL.
6. **Commented-out SELECT with no/!partial replacement** — verify a new active statement exists.
7. **#EC on a continued (non-terminating) line** — may not clear ATC and can read oddly.

**Required structural syntax checks (since no ABAP compiler here):** per file verify — marker begin==end; `SELECT`==`ENDSELECT` count delta unchanged or matched (CHANGE_SINGLE adds 1 each); `LOOP`==`ENDLOOP`, `IF`==`ENDIF`, `DO/WHILE`==`ENDDO/ENDWHILE` balance unchanged vs original; no `SORT … BY` token containing `=`/`"`/`-`; balanced `CONV #( … )` parentheses; every commented-old block has a corresponding active replacement; latin-1+CRLF + trailing newline preserved. Flag any file failing and do NOT trust it.

**Config (ZATC) tables — driven data, NOT in repo:** `zatc_process_all`, `zatc_process1`, `zatc_process_dte` (cols: priority, description, check_title, note, `srch_tem`=object/search term, `ref_obj_type` DTEL/DOMA/TABL/TRAN/FUNC, look/look2, zcomment, `fix_by` e.g. 'FIT GAP', `solution`='X' solvable, `correction_value`=replacement e.g. new data element). These supply the **DTEL/DOMA → new data element** mappings. **ACTION RULE from Vaibhav:** when working a program where a data element (DTEL/DOMA) needs changing and the mapping isn't in memory, **ASK him to supply the ZATC table data** for it. Other lookup data (ARS table→CDS, DDLS fields) is already in [[atc-mapping-references]].

## (atc-migration-agent)


A second, more advanced remediation system beyond the in-system ABAP `ZATC_RESULT_CORRECTION` ([[atc-correction-program]]): a **cloud CAP/Node service ("Migration Agent")** that drives ATC bulk-fix runs through ADT + Claude LLM + deterministic pre-passes + per-system self-learning. Source archived in ATC project `tool/migration-agent/` (migration-worker.js, migration-classifier.js, bdc-bapi-mapping_1.js [4.3MB], fix-knowledge.js, 07-bdc-conversion.json, migration-system-prompt.md). See [[atc-approach-decision]], [[atc-mapping-references]].

**Run lifecycle (migration-worker.js):** `QUEUED → DISCOVERING → ENRICHING → CLASSIFYING → FIXING → [VERIFYING] → COMPLETED`. Dispatcher sweeps QUEUED + stale (heartbeat>90s) runs; per-run coroutine checkpoints each phase. `objectFilter` scopes a run to a list of programs (pilot mode 10–15). Reads findings from SATC_* tables / ATC REST on the destination system.

**Classifier (migration-classifier.js, pure-CPU, first-match-wins) → fixability:**
- `NOT_FIXABLE`: already exempted (excValidity=Y/exemptionId); pseudo-pragma already present; generated/`$TMP`/`$SYS`/`S_*` package; **SAP-standard object** (objectName not `Z*`/`Y*`/`/ns/`/`LZ*`/`LY*`/`SAPLZ*`/`SAPLY*` → never modify standard, e.g. LEDI1U28/LV45AF01); Cat-A "no alternative" removed DDIC; **P1 functional-redesign** (Simpl. Item Cat **B** "functionality unavailable" / **W** "non-strategic") with no recipe.
- `MANUAL_REVIEW`: **generated FG include matching `$\d+$`** (ADT write → HTTP 403 ExceptionResourceNoAccess, regenerated by Function Library → fix manually in SE38; proven across 3 runs for ALL finding types); **FLE on RFC/FM interface parameter** ("used by RFC-Function parameter" → SE37, MATNR covered by note 2438131); finding with no check title AND no message (data-quality gate); P2/P3 without autoApprove.
- `AUTO_DETERMINISTIC`: SATC `HAS_QUICKFIXES=X` → let ADT quickfix apply it (no LLM).
- `AUTO_LLM`: P1 always; P2/P3 when `run.autoApprove`.
- **Cost guard:** func-unavail (Cat B/W) is hard-skipped at **P1 only** (no LLM tokens); P2/P3 fall through to take the recommended `#EC`.
- **Carve-outs that MUST reach the LLM even when tagged "functionality unavailable" (they have real recipes):** DB Operation SELECT/UPDATE/DELETE (→CDS/BAPI); TRAN/BDC/CALL TRANSACTION (→BAPI/FM, e.g. XD03→BP, MB03→MIGO, ME21→ME21N); CALL FUNCTION / FUGR (successor FM recipes); credit mgmt `KNKK`/`KNKA`/`SO66`/`SO67` (→UKMBP_CMS_SGM / UKMBP_CMS / V_UKM_ITEM / UKM_TOTALS); rebate `VBOX` (→`SD_REBATES_GET_INVOICES_IM`); drop-in successor tables `S066/S067`, stock `MARD/MARC/MCHB/…` (→`NSDM_V_<table>`), `VBUK/VBUP` (→`V_VBUK_S4`/`V_VBUP_S4`); released-CDS tables MARA/MKPF/MSEG/EKKO/EKPO/EBAN/VBAK/VBAP/VBFA/VBRK/VBRP/AUFK/AFKO/AFPO/QALS… when not Cat-A.

**BDC→BAPI conversion (bdc-bapi-mapping_1.js + 07-bdc-conversion.json + customer FM `Z_BDC_FM_MAP_GET`/`ZBDC_FM_MAPPER`):** huge hardcoded **BDC tcode → S/4 target API** map (~36k targetFm/targetClass entries); each tcode → ordered candidate array (priority CREATE>CHANGE>DISPLAY>OTHER); `getBdcBapiTarget()` default pick, `getBdcBapiTargets()` all candidates with fallback loop until `Z_BDC_FM_MAP_GET` returns a non-zero match. The wrapped ABAP maps BDC FNAM/FVAL→target params by **DD03L rollname matching**. Golden patterns: (1) CALL TRANSACTION→BAPI create (e.g. VA01→`BAPI_SALESORDER_CREATEFROMDAT2`); (2) BDC→Master-Data Layer API class (XK01→`VMD_EI_API`, customer→`CMD_EI_API`); (3) FNAM/FVAL→BAPI field by rollname, **drop dynpro-control fields** (BDC_OKCODE/BDC_CURSOR/OK-codes), keep+map every business field. **Quality gates:** target RELEASED for ABAP Cloud & exists on target release; evaluate BAPIRET2 for E/A; explicit `BAPI_TRANSACTION_COMMIT`/`ROLLBACK` (never rely on implicit dialog commit); no `MESSAGE` in library code (return the table); no classic-table SELECT (use released CDS).

**Self-learning (fix-knowledge.js, Tier-1 deterministic, no embeddings, per-system, gated by MIGRATION_LEARNING):** `computeSignature = checkId | dependsOn | objectType` — object-AGNOSTIC so the same KIND matches across programs; `dependsOn` = referenced object (not the scanned object), else `NOTE:<n>` from message, else DDIC name. `ingestFromFinding` upserts a before→after exemplar **only when a fix is ATC-VERIFIED** (verified never downgraded). `buildGroundingForFindings` exact-matches signatures and injects up to 4 verified exemplars as few-shot grounding ("apply the SAME approach, adapt names; proven, not guesses"); `reuseCount` = times an exemplar was reused. Pure SQL key lookup — works on any tenant.

**System prompt (migration-system-prompt.md):** SAP S/4 migration expert; knows Simplification List (BSEG→ACDOCA/I_JournalEntry, KONV→PRCD_ELEMENTS, KNA1/LFA1→BP, credit FKMC→UKM, output NAST→BRF+); workflow read_abap_program → line-by-line analyze → remediate → migration-report table → corrected code → summary; ATC bulk-fix tools target SATC_* tables / ATC REST (treat as safe, users invoke by name).

**Where it fits vs ZATC program:** ZATC_RESULT_CORRECTION = in-system ABAP, edits source via RPY/ADT directly. Migration Agent = external orchestrator that classifies (this CPU layer), routes to ADT quickfix / LLM / manual, runs BDC→BAPI deterministic pre-pass, verifies via ATC re-run, and learns. Its classifier recipes corroborate/extend [[atc-mapping-references]] (KNKK/S066/VBOX/VBUK successors).
